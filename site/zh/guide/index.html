Jev 指南：类型化决策、概率与评测

基于一手来源介绍 Jev、决策原语、置信度、评测方法和独立模型实现。

Jev 是什么？

Jev 是 TypeSafe 的 System One 模型。请求提供状态和类型化问题，响应返回边界明确的答案与概率，供应用代码完成分类、路由或复核。 TypeSafe 官方介绍

TypeSafe 将其训练方法称为 Reinforcement Learning for Calibrated Decisions，简称 RLCD。这是厂商对方法的描述，并不足以重建 Jev 的架构或训练过程。 TypeSafe 发布文章

类型化决策与 LLM 的结构化输出有什么区别？

类型化决策接口在推理前规定允许的候选答案。生成式 LLM 也能通过约束解码产生结构化输出。仅凭接口形式，不能判断哪个模型更准确、校准更好或效率更高。 XGrammar 论文

格式合法的答案仍可能选错。应区分 schema 合法性与语义正确性，并在自己的任务上测试模糊指令、对抗输入和选项顺序变化。 Jev 1.13 已知局限

Choice、Score 和 Noul 分别返回什么？

Choice 从调用方定义的候选项中选择，返回所选项、所有候选项的概率及置信度，适合有限类别或动作选择。 Choice 文档

Score 对文字描述的有序等级进行评估，返回等级编号的概率加权均值、概率分布与置信度；它不是从输入中抽取的精确测量值。 Score 文档

Noul 返回是非命题为真的概率，没有独立的 confidence 字段。接近中间的数值表示不确定性，不一定表示该属性处于中等程度。 Noul 文档

置信度就是答案正确的概率吗？

不能直接等同。TypeSafe 根据返回的分布计算置信度。例如，Choice 有四个选项，最高概率为 0.70 时，confidence 为 0.60；Score 使用不同公式。校准关注多次预测中的实际发生频率，不保证某个答案一定正确。 置信度文档

怎样评估决策质量与概率校准？

分别评估预测质量与概率质量。除准确率或适合任务的误差指标外，还应查看可靠性图，以及 Brier score、log loss 等适当评分规则。使用独立测试数据，不在最终测试集上调节阈值。 校准研究 · 适当评分规则

对于拒答或升级处理，应报告覆盖率和已接纳案例中的错误，并验证后备模型能否纠正错误。固定模型版本与提示词，单独测量端到端延迟、失败和成本。这是评测方案，不是本项目对 Jev 已取得的实验结果。 SelectiveNet · 模型版本

官方 SDK 和独立模型就是发布的 Jev 权重吗？

官方 SDK 是 TypeSafe 托管 API 的客户端，并非 Jev 检查点。Laya 等独立项目发布的是各自的模型材料。问题类型相似或 API 兼容，不证明架构、行为或准确率相同。 官方 Python SDK · Laya 模型卡

应分别检查每个版本的模型卡与许可。例如，Bespoke Nimble 9B v3 声明采用 CC BY-NC 4.0，限制商业用途。不能把所有可公开下载的模型材料都称为不受限制的开源模型。 Bespoke Nimble v3 模型卡

从哪里查找研究和基准证据？

从固定版本的实证论文及其公开代码、数据入手。覆盖多数据集的 Jev 基准研究可作为入口，但结果仍由作者报告，并非本资源库已独立复现。 Jev 基准论文 v1 · 配套评测代码

TypeSafe WorkflowEvals 公开工作流和模型生成的参考标签；与这些参考结果一致，不等于人工标签上的准确率。社区 Decision Index 还包含私有测试，因此公开排名不代表整个评测都能独立复现。 WorkflowEvals · Decision Index 方法快照
